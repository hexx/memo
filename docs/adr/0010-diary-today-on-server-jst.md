# 日記の「今日」はサーバーが Asia/Tokyo 固定で決定する

## Status

Accepted（2026-09-24、日記機能の設計セッション）

## Context

日記は暦日（`YYYY-MM-DD`）に紐づく。Cloudflare Workers は UTC で動作するため、日本時間の 0:00〜9:00 の間は UTC 上ではまだ前日である。Web の一般的な日記アプリはクライアントのローカル日付で「今日」を決めるが、端末の時計・タイムゾーンに依存する。クライアント日付送信（推奨候補）、UTC、固定タイムゾーンの選択肢があった。

## Decision

「今日」はサーバーを唯一の決定者とし、固定タイムゾーン `Asia/Tokyo` で判定する。日記作成で日付を省略した場合はサーバーが `Asia/Tokyo` の今日を割り当てる。指定された日付は形式・実在日付・未来日（`Asia/Tokyo` 基準）を検証して採用する。クライアントの日付ピッカーの初期表示だけは、表示目的で `Asia/Tokyo` の今日を JS で計算する。

## Rationale

- 端末の時計ずれ・タイムゾーン設定の影響を受けない
- 単一ユーザーの日本語向けアプリであり、タイムゾーン設定という概念を持ち込む必要がない
- 日本は DST がないため、UTC+9 の固定オフセットで常に正しく計算できる

## Considered Options

- **クライアントのローカル日付を送信**: 実装は最も簡単だが、端末依存（時計ずれ・海外渡航）で「今日」が変わるため推奨しなかった
- **UTC 基準**: 日本では 0:00〜9:00 が前日として扱われ、日記の「今日」として不自然
- **ユーザー設定のタイムゾーン**: 単一ユーザーアプリに設定画面を増やす価値がない（YAGNI）

## Consequences

- 海外滞在中でも日記の「今日」は日本時間のカレンダーに従う
- `created_at` / `updated_at` は従来どおり UTC の ISO 8601 のまま（日記の日付とは別物）
- 将来タイムゾーン設定が必要になった場合は本 ADR を置き換える
